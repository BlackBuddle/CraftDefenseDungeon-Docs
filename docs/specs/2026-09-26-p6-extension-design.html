P6 종족·지역 확장 프레임워크 + 관리자 도구 설계서

  • 상태: 승인 (2026-09-28)

  • 작성: 2026-09-26

  • 상위 문서: 게임 기획서 — 결정 번호(D…)는 기획서 2장 "결정 기록"을 따른다. 종족별 대응표는 기획서 4.7.

  • 앞 단계: P2, P3, P4, P5, P8

  • 이 단계의 결정: D104~D106, D112~D116 (전제: D2·D31·D34·D35·D79)

1. 목적과 범위

출시 뒤에도 지역과 종족을 계속 더할 수 있는 틀과, 그 콘텐츠를 만드는 개발자용 도구, 그리고 배포·세이브 호환 규칙을 정의한다.

포함포함하지 않음 (담당 단계)
종족 규칙의 공통 틀(대응표의 칸)각 종족·지역의 이름과 설정 (P7)
지역 데이터, 콘텐츠 참조 규칙실제 DLC 가격·출시 일정 (운영)
에디터 관리자 도구의 기능모드 도구 자체 (출시 후)
DLC 묶음, 모드 대비, 세이브 호환
오라클 플레이어블의 승패

2. 종족 규칙의 공통 틀 (D104·D116)

기획서 4.7의 대응표에서 칸을 공통 틀로 삼는다. 모든 종족은 같은 칸을 채운다.

칸인류 제국퓨라시온오라클(플레이어블)
자원채굴·조합감염 영역이 광맥을 먹음제단의 제물사망에서 개념 에너지
확장굴착 + 굴착 가능 영역감염 영역신성영역없음(관전자)
유닛도구 → 병참스폰 + 합체신성영역에 소환, 제사장은 이동레드존·화신
특수 기믹병과, 재무장감염심판, 봉인된 악마레드존
영웅장교 + 동료동화강림수렴(화신)
판 종료본부 파괴주 감염 핵 파괴본진 파괴 + 악마 3분3분 동안 사망 0(D115)
판 사이 이야기새 장교 파견새 포자새 제사장단개념 재응결
영구 재화 흐름송금·세금유전자 저장천상 봉헌개념 공명
작전 계승작전 계획서영역·합체 비율 기억제단·신성영역 배치자주 쓴 개념 강화

  • 각 칸은 코드 규칙 + 데이터 값으로 나뉜다. 예) "감염 영역 스폰"의 동작은 코드, 스폰 속도와 합체 비율은 데이터.

  • 완전히 새로운 기믹은 코드가, 기존 기믹의 변형은 데이터만 필요하다. 1차 버전에서 네 종족의 규칙 조각을 모두 만들어 두므로(적으로서), 이후 종족 DLC는 대부분 데이터·에셋 작업이다.

  • 유닛 데이터는 우리 유닛과 적 유닛이 같은 형식을 쓴다(D79). 종족을 플레이어블로 바꿀 때 유닛을 다시 만들지 않는다.

2.1 오라클 플레이어블의 승패 (D106·D115·D116)

  • 승리: 모든 유닛이 죽거나 자원이 모두 바닥남.

  • 패배: 3분 동안 아무도 죽지 않으면 개념이 흩어진다.

3. 지역 데이터 (D31·D34·D35·D116)

항목내용
격자 좌표7×7 격자 안의 위치(D49)
크기기본 128×128
암반등급 범위, 노이즈 설정
자원금속·결정 비율, 희귀 자원 종류와 양
환경용암·독가스·불안정 암반 비율
등장 종족포탈로 나오는 종족과 비율
유물표이 지역에서 나오는 유물
레드존 빈도 계수오라클 레드존이 이 지역에서 얼마나 자주 생기는지
켜기·끄기게임에 나올지
필요한 DLC없으면 무료 지역

4. 에디터 관리자 도구 (D35·D112·D116)

Unity 에디터 안의 전용 창(EditorWindow)이다. 게임 빌드에는 들어가지 않는다.

기능내용
격자 지도7×7 격자로 지역을 보고, 새 지역을 만들고(복제), 켜고 끈다
구성 편집3장의 항목을 표로 편집
지형 미리보기시드를 바꿔 가며 생성된 지형을 2D 지도로 본다(P2 3장 생성기 그대로 사용)
검사빠진 값, 격자 겹침, 없는 ID를 가리키는 참조, 범위를 벗어난 숫자를 경고
시험 플레이고른 지역과 시드로 바로 판을 시작
다른 데이터 탭종족·유닛·개념·유물·강화 데이터도 같은 창에서 편집

5. 배포와 DLC (D113·D116)

  • 지역은 무료 업데이트로 더한다(데이터 추가 + 패치).

  • 종족은 유료 DLC다.

    • 적으로서의 퓨라·시온, 레드존 오라클은 모든 플레이어에게 있다.

    • DLC는 그 종족을 플레이어블로 쓰는 권리 + 전용 장교·모델·지역이다.

    • Steam DLC 소유를 확인해 켠다.

  • 콘텐츠 묶음은 Unity Addressables(에셋을 묶음 단위로 나눠 불러오는 기능)로 나눈다.

6. 모드 대비 (D114·D116)

지금 만드는 것은 없다. 나중에 문이 막히지 않도록 두 가지만 지킨다.

  1. 데이터끼리는 파일 경로가 아니라 ID로 서로를 가리킨다.

  2. 데이터 형식에 버전 번호를 붙인다.

나중에 외부 파일을 읽어 같은 ID 체계에 넣으면 모드(Steam 창작마당)가 된다.

7. 세이브 호환 (D116)

  • 영구 데이터(P8 9장)는 콘텐츠를 ID로 저장한다. 사라진 ID는 건너뛴다. 콘텐츠가 늘어도 기존 세이브는 깨지지 않는다.

  • 판 데이터(중단 저장)에는 게임 버전을 적는다. 새 버전과 맞지 않으면 그 판의 영구 보상을 정산하고 판을 닫는다.

8. 구조 (Unity 구현 방향)

요소하는 일
RaceDef2장의 칸을 채우는 데이터 + 각 칸이 쓸 규칙 조각의 ID
규칙 조각(코드)칸마다 하나의 공통 틀(예: IEconomyRule)과 종족별 구현 — 1차에 네 종족분
RegionDef3장의 항목
ContentRegistry모든 데이터를 ID로 찾아 주는 목록. DLC 소유에 따라 켜고 끔
ContentValidator4장의 검사. 에디터 도구와 자동 테스트가 함께 씀
RegionAdminWindow4장의 에디터 창

  • 칸마다 공통 틀을 두는 이유: 구현이 1차에 이미 넷(인류·퓨라·시온·오라클)이라, 공통 틀 없이는 종족마다 분기문이 퍼진다.

9. 테스트와 검증

무엇을어떻게
데이터 검사일부러 깨뜨린 데이터(빠진 값, 없는 ID, 격자 겹침)를 넣으면 검사기가 모두 잡는지
전체 콘텐츠모든 지역·종족 데이터가 검사를 통과하는지 — 빌드 전에 자동으로
DLC 켜기·끄기DLC가 없으면 해당 종족을 플레이어블로 고를 수 없고, 적으로는 그대로 나오는지
세이브 호환콘텐츠 ID를 하나 지운 세이브를 불러와도 깨지지 않는지
판 데이터 버전버전이 다른 중단 저장을 불러오면 보상 정산 후 닫히는지
오라클 패배3분 동안 사망이 없으면 패배하는지

  • 이 단계의 결정: D122~D128 (전제: D1·D8·D28·D36·D40, 4.1 설계 원칙, P6·P8 설계서)

1부. P1 프로젝트 준비

1.1 도구 (D122·D123·D124)

항목선택
엔진설치 시점의 최신 Unity 6 LTS. 개발 중에는 큰 버전을 올리지 않고 패치만 받는다
렌더 파이프라인URP (로우폴리 3D, Bloom 발광)
코드 편집기Visual Studio 2022 Community
입력새 Input System
테스트Unity Test Framework EditMode

1.2 저장소와 폴더 (D124)

D:\CraftDefenseDungeon\
  docs\                    기획서·설계서 (지금 그대로)
  Game\                    Unity 프로젝트
    Assets\_Project\
      Scripts\
        Simulation\        게임 규칙 — 순수 C#, UnityEngine 참조 금지
        View\              화면·입력 (MonoBehaviour)
        Online\            운영 서버 연결 (2부)
        Editor\            관리자 창 (에디터 전용, P6)
      Data\                ScriptableObject 데이터
      Tests\EditMode\      규칙 테스트
      Art\  Prefabs\  Scenes\

  • 각 Scripts 폴더는 어셈블리 정의(asmdef) 하나다. 참조 방향: View → Simulation, View → Online, Editor → 전부. Simulation은 아무것도 참조하지 않고 UnityEngine도 못 쓴다(asmdef의 "No Engine References").

  • 데이터(ScriptableObject)는 판이 시작될 때 순수 C# 값으로 옮겨 Simulation에 넘긴다.

1.3 시뮬레이션 루프 (D124)

  • 초당 20틱 고정. View가 경과 시간을 모아 틱을 돌리고, 화면은 틱 사이를 보간한다.

  • 플레이어 입력은 명령 객체로 틱에 들어간다(D8). 난수는 시드 기반 자체 생성기(P2 3장).

1.4 패키지

처음부터나중에
URP, Input System, Test FrameworkAddressables (종족 DLC, P6), Steamworks.NET (리더보드·클라우드·Steam 로그인, P8·2부), UGS 패키지 (2부)

회색 박스 프로토타입에는 "처음부터"만 쓴다.

1.5 Git 설정 (D124)

  • Unity용 .gitignore (Library, Temp, Obj, Build, Logs, UserSettings 제외).

  • Git LFS: *.fbx *.png *.psd *.wav *.ogg *.mp3 *.tga *.exr.

  • Project Settings: Asset Serialization = Force Text, Version Control = Visible Meta Files.

1.6 설치 순서 (체크리스트)

  1. Unity Hub 설치

  2. Unity 6 LTS 설치 — 모듈: Visual Studio 2022 Community, Windows Build Support

  3. Git LFS 설치 (git lfs install)

  4. Unity Hub → 새 프로젝트 → Universal 3D (URP) 템플릿 → 위치 D:\CraftDefenseDungeon\Game

  5. Project Settings에서 1.5 설정, Package Manager에서 Input System·Test Framework 확인

  6. 1.2 폴더와 asmdef 만들기 → 빈 EditMode 테스트 하나가 통과하는지 확인

2부. P9 운영 서버

2.1 목표 (D125)

  • 관리자가 일부 내용을 서버로 통제한다.

  • 관리자가 플레이어의 진행을 확인한다.

  • 서버 부담은 적어야 한다. 게임은 서버가 없어도 돌아가야 한다.

2.2 통신은 두 번뿐 (D126)

언제무엇크기
게임을 켤 때관리자 설정 받기 → 로컬에 캐시수 KB
판이 끝날 때플레이어 진행 요약 올리기약 2 KB

  • 게임 중에는 서버와 통신하지 않는다.

  • 서버에 닿지 못하면: 설정은 마지막 캐시(없으면 기본값), 요약은 로컬 대기열에 두었다가 다음 접속 때 보낸다.

2.3 관리자가 통제하는 것 (D127) — UGS Remote Config

항목예게임 쪽 처리
밸런스 수치세율 표, 위협도 증가량, 레드존 구간, 포탈 간격, 오프라인 상한데이터 기본값을 덮어씀. 범위를 벗어나면 기본값
지역 운영·기간 이벤트빌드에 들어 있는 지역 켜기·끄기, "이번 주 침공 강화", 보상 배율시작·종료 시각이 있는 값
공지·최소 버전브리핑 상단 콘실리움 공지, 최소 빌드 번호빌드가 낮으면 업데이트 안내
리더보드·플레이어 조치불가능한 기록 숨김, 제재, 세이브 복구 지원대시보드·Steam Web API에서 관리자가 처리

  • 설정은 판이 시작될 때만 적용된다. 판 도중에 값이 바뀌지 않아 결정성(D8)이 깨지지 않는다. 적용된 설정 버전은 판 데이터에 기록한다.

2.4 관리자가 확인하는 것 (D128) — UGS Cloud Save + Player Management

플레이어별 진행 요약만 올린다. 판 보고서와 전체 통계는 서버로 보내지 않는다.

요약 항목
메리툼 등급, 누적 송금액
재화 3종(트리부툼·시길룸·렐리퀴아 파편)
강화 트리 단계, 영입한 장교·동료, 유물과 성급
판 수, 개인 최고 기록(P8 8장), 마지막 접속, 빌드 번호

  • 관리자는 UGS 대시보드의 Player Management에서 플레이어별로 본다.

  • 리더보드 검증: 최고 기록이 누적 플레이 판 수·송금액에 비해 불가능하면 표시해 두고 관리자가 판단한다. 세이브는 여전히 Steam 클라우드가 원본이다(P8).

2.5 플레이어 식별

  • Steam 로그인(UGS Authentication의 Steam 연동). 별도 계정 없음. Steam ID와 게임 데이터만 다룬다 — 출시 전 개인정보 처리방침 필요.

2.6 게임 쪽 구성

구성하는 일
IOnlineServices온라인 기능의 틀. 구현은 UGS용과 오프라인용(아무것도 안 함) 두 가지. 나중에 Supabase용을 더할 수 있다
RemoteConfigService시작할 때 설정을 받아 캐시하고 범위를 검사
ProgressSummaryQueue판 종료 시 요약을 로컬 파일에 넣고, 온라인일 때 올림

  • Simulation은 서버를 모른다. View가 판 시작 때 설정을 데이터로 넘기고, 판 종료 때 요약을 대기열에 넣는다.

2.7 비용과 전환 (D126·D128)

  • 공식 요금(2026-09-28 확인) 기준, 요약만 올리면 Analytics를 쓰지 않아 15만 MAU에서도 월 약 $1(Cloud Save)이다. Authentication·Remote Config는 무료.

  • 주의: 무료 한도를 넘었는데 결제 수단이 없으면 30일 유예 후 서비스가 정지된다 → 출시 전 결제 수단 등록.

  • 요금이 바뀌거나 통제력이 더 필요해지면 IOnlineServices에 Supabase + Cloudflare 구현을 더해 갈아탄다(월 $25 고정 수준).

3. 테스트와 검증

무엇을어떻게
asmdef 경계Simulation에서 UnityEngine을 쓰면 컴파일이 실패하는지
틱같은 명령·시드로 두 번 돌리면 같은 상태인지
설정 범위 검사범위를 벗어난 원격 값이 기본값으로 바뀌는지
오프라인서버 없이 게임이 시작되고 판이 끝나는지, 요약이 대기열에 남는지
대기열다시 온라인이 되면 쌓인 요약이 한 번씩만 올라가는지
판 중 설정 고정판 도중 원격 값이 바뀌어도 그 판의 값이 그대로인지
